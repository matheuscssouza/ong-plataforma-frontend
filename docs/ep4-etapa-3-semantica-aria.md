# EP4 · Etapa 3 — Alterações semânticas e WAI-ARIA

| Elemento modificado ou tag implementada | Justificação e impacto na acessibilidade |
|---|---|
| `Landmarks: <header>, <nav aria-label="Navegação principal">, <main>, <footer id="contato">` | Substituem divs genéricas por marcos que o leitor de tela lista e permite pular direto (banner, navegação, conteúdo principal, rodapé). O nav ganhou rótulo para ser identificado mesmo que existam outros menus. |
| `<section> e <aside> com aria-labelledby apontando para o próprio título` | Transformam blocos em regiões nomeadas: o leitor de tela anuncia "região Campanhas de doação" e a pessoa navega entre elas. Os títulos seguem h1 a h4 sem pular níveis. |
| `Link "Pular para o conteúdo" + <main tabindex="-1">` | Primeiro item da página, visível ao receber foco pelo teclado. O tabindex="-1" (alteração desta etapa) garante que o foco chegue de fato ao conteúdo em qualquer navegador, sem passar de novo pelo menu. |
| `<button class="menu-botao" aria-expanded aria-controls="menu-principal">` | O menu hambúrguer é um botão nativo (acessível por Enter e Espaço), e aria-expanded informa se está aberto ou fechado. O próprio CSS lê esse atributo, então estado visual e anunciado nunca divergem. Esc fecha e devolve o foco. |
| `Submenu: <button aria-label="Submenu de Projetos" aria-expanded> e aria-current="page"` | A seta, que não tem texto visível, recebeu nome acessível. aria-expanded anuncia o dropdown aberto, e aria-current marca no menu a página atual, atualizado pela SPA a cada troca. |
| `<dialog class="modal" aria-labelledby> aberto com showModal()` | Usei o elemento nativo em vez de uma div: ele já prende o foco dentro do modal, fecha com Esc e deixa o restante da página inerte. aria-labelledby liga o modal ao título, que é anunciado ao abrir. |
| `Formulário: <fieldset>/<legend>, <label for>, required e autocomplete` | Todo campo tem rótulo associado e os grupos têm legenda. required é anunciado como "obrigatório" e autocomplete (name, email, tel, postal-code) permite o preenchimento automático (WCAG 1.3.5). |
| `Erros de campo: aria-invalid="true" + aria-describedby para a mensagem injetada` | Quando um campo falha, o JavaScript marca aria-invalid e liga a mensagem específica ao campo por aria-describedby: o leitor de tela lê "inválido" e o motivo do erro. Ao corrigir, os atributos são removidos. |
| `Resumo de erros com role="alert" e toasts com role="status" aria-live="polite"` | Mensagens que surgem após uma ação são anunciadas sem mover o foco (WCAG 4.1.3). O resumo lista os erros com links para cada campo, e os toasts de confirmação são lidos sem interromper a pessoa. |
| `SPA: região aria-live "Página carregada: …", aria-busy no <main> e foco no <h1>` | Nova nesta etapa: a troca de página sem recarregar não era anunciada por todos os leitores de tela. Agora a região aria-live informa a página nova, aria-busy sinaliza o carregamento e o foco vai para o título. |
| `Asterisco de obrigatório com aria-hidden="true" + texto oculto "(obrigatório)"` | Alteração desta etapa: o leitor de tela lia "Nome completo asterisco". Como o required já é anunciado, o asterisco ficou só visual; na legenda do grupo de rádios, que não tem required próprio, entrou o texto oculto. |
| `<canvas role="img" aria-label> + <table> com <caption> e scope; ícones com aria-hidden` | O gráfico tem descrição textual e uma tabela de dados equivalente, que aparece sozinha se o gráfico falhar. Ícones SVG decorativos e a logo ao lado do nome ficam fora da leitura (aria-hidden e alt=""). |
